# CS2 Analytics — Project Memory

> **Единая точка входа для любого нового чата и разработчика.**
>
> Рабочая ветка: `faceit-dev`. Эта память описывает только подтверждённое состояние DEV. Production не входит в область текущей работы.

## Начало работы — читать в этом порядке

1. [CURRENT_STATE.md](CURRENT_STATE.md) — что реально реализовано сейчас, последние подтверждённые изменения и незакрытые задачи.
2. [NEW_CHAT.md](NEW_CHAT.md) — обязательная инструкция помощнику, включая безопасный порядок восстановления контекста.
3. [PROJECT_MASTER.md](../../PROJECT_MASTER.md) — цели, ограничения и принципы продукта.
4. [TECHNICAL_STATE.md](../../TECHNICAL_STATE.md) — подробная техническая история и актуальные контрольные точки.
5. [ARCHITECTURE.md](../../ARCHITECTURE.md) — устройство приложения и данные.
6. [DESIGN_SYSTEM.md](../../DESIGN_SYSTEM.md) и [FACEIT_REFERENCE.md](../../FACEIT_REFERENCE.md) — визуальные правила и исследование референсов.
7. [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) — смысловая история законченных задач.
8. [DECISIONS.md](../../DECISIONS.md) — принятые решения и ограничения.
9. [QUALITY_HISTORY.md](QUALITY_HISTORY.md) — фактические результаты тестов и проверок.
10. [ROADMAP.md](../../ROADMAP.md) — очередь и статус будущей работы.

После чтения документов помощник **обязан заново проверить GitHub branch HEAD и последние коммиты**. Документ не заменяет проверку живого репозитория.

## Как фиксируется каждая задача

После законченной задачи помощник должен:

1. Записать задачу в DEVELOPMENT_LOG.md: цель, фактическое поведение до/после, изменённые файлы, важные детали реализации, commit SHA.
2. Обновить CURRENT_STATE.md: только актуальные подтверждённые факты; устаревшие сведения заменить или явно пометить как историю.
3. Записать новые решения в корневой DECISIONS.md, если они действительно приняты владельцем.
4. Добавить фактические результаты в QUALITY_HISTORY.md: команда/CI run, commit SHA, passed/failed, тип проверки и ограничения.
5. Обновить TECHNICAL_STATE.md, ARCHITECTURE.md, DESIGN_SYSTEM.md или ROADMAP.md, когда меняется соответствующая область.
6. Проверить ссылки и согласованность документов.
7. Зафиксировать всё в `faceit-dev` и сообщить пользователю точный commit SHA.

**Не нужно создавать запись ради каждого микрошагового промежуточного изменения.** Записывается каждая законченная работа/логический пакет изменений. Если задача прервана, её статус и незаконченные пункты фиксируются как IN PROGRESS, а не как завершённые.

## Уровни достоверности

Каждое утверждение должно быть понятно классифицировано:

- **Подтверждено кодом** — проверен актуальный исходник.
- **Подтверждено тестом/CI** — есть конкретный результат и commit SHA.
- **Подтверждено browser QA** — действительно проверено в браузере с указанием среды/viewport.
- **Подтверждено deployment** — известен deployed SHA и среда.
- **Решение владельца** — пользователь явно согласовал.
- **Не проверено / предположение / план** — никогда не выдавать за готовую функцию.

Зелёный CI не доказывает browser QA, правильность live data или успешный deployment.

## Автоматизация и её границы

Существующий workflow `.github/workflows/project-memory.yml` автоматически дополняет корневой CHANGELOG.md метаданными push-коммита и изменёнными путями.

Он **не читает частные разговоры ChatGPT и не может самостоятельно объяснить смысл изменения**. Поэтому смысловые записи в этой папке обязан создавать помощник в рамках завершения задачи. Не дублировать автоматический commit log вручную.

## Правила безопасности

- Только `faceit-dev`, если владелец явно не разрешил иное.
- Перед изменением заново проверить branch HEAD.
- Не менять `main`, production Supabase или production deployment.
- Не выполнять SQL, migrations, RLS, grants или DB writes без отдельного разрешения.
- Не деплоить и не проводить browser QA без отдельного разрешения.
- Не записывать секреты, токены, приватные данные аккаунтов.
- Не придумывать метрики, тестовые результаты, визуальные проверки или состояние функций.

## Последняя актуальная точка

Смотри [CURRENT_STATE.md](CURRENT_STATE.md). Дата и SHA там должны соответствовать последней проверенной версии, а не дате последнего сообщения в чате.
